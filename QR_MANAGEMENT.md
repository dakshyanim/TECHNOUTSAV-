# Admin QR management

Open `/admin/qr` from the admin dashboard to generate/view all active question codes, or `/admin/qr/<question UUID>` for one question. Each card shows its challenge code, internal question UUID, full question text and absolute challenge URL. SVG and high-resolution PNG downloads are protected admin endpoints. Inactive/missing questions return 404. Participant sessions cannot access QR management or downloads.

Set APP_ORIGIN in ignored .env.local to the stable event application origin, such as https://your-event-domain.example. Restart the app. Origins must use HTTP(S), contain no credentials/path/query/fragment, and match the origin students use. Production QR generation requires this setting. Development defaults to http://localhost:3000; for phones use a reachable LAN/deployed address instead. localhost on a phone points to the phone, not the event server. Test a scan on an actual student phone before printing the final set.

Each QR encodes only `<APP_ORIGIN>/challenge/<challenge_code>`. Correct answers and participant/session data are neither queried by QR management nor included in the QR payload. Existing question challenge codes remain unchanged when question text/points are edited. QR generation creates no database records and needs no new migration.

SVG downloads scale without loss. PNGs use twenty pixels per module; both are opaque black on white with a four-module quiet zone and Q error correction. Do not crop the border, stretch the code, or place graphics over it. The print sheet lays out one question per A4 page with an 80mm square QR. Print all or Print this question opens the browser print dialog, which also supports Save as PDF. Use 100% scale; turn browser-added headers/footers off if desired. Very long question text may spill onto additional pages rather than being truncated. Print once and scan under venue lighting before making copies.

Verification: `npm run test:qr` decodes generated PNGs and verifies exact URL payloads, quiet-zone pixels, SVG generation and invalid-origin/code rejection. The browser harness also covers admin-only access, active-only lists, protected PNG/SVG downloads and print layout. Hosted Supabase/phone verification requires configured credentials and a reachable application URL.

Completed local checks: QR decoding and TypeScript passed. In the isolated browser test, normal participants were denied QR pages/downloads; ten active questions were generated; an inactive question was excluded and returned 404; SVG/PNG downloads succeeded and both the downloaded PNG and rendered print SVG decoded to the exact challenge URL; the question UUID was visible; individual printing worked; and the A4 print sheet contained ten pages, with 80mm QR images. The browser test uses real local PostgreSQL and generated QR images with simulated Supabase transport. It does not prove hosted Supabase connectivity or scanning on a physical phone.
